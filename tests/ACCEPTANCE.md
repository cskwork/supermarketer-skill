# Acceptance contract

## Structural

- [ ] `SKILL.md` has valid frontmatter with a trigger-focused description.
- [ ] Every mode in the router maps to an existing reference and primary output.
- [ ] Every local Markdown reference resolves.
- [ ] Every producer role has an independent review path.
- [ ] Templates contain stable state, evidence, claim, asset, measurement, and approval anchors.
- [ ] The root skill remains a router rather than embedding every playbook.

## Marketing integrity

- [ ] Product truth precedes persuasive factual copy.
- [ ] Every factual, quantitative, comparative, testimonial, promotional, pricing, or availability claim resolves to appropriate evidence.
- [ ] Current channel specs are dated and sourced.
- [ ] No synthetic testimonial or fabricated proof is represented as real.
- [ ] Rights, privacy, generated-asset lineage, and accessibility are recorded.
- [ ] Regulated contexts create a current jurisdiction and specialist-review decision gate.

## Media

- [ ] `STATIC` requires an actual rendered file.
- [ ] `IMAGE` fallback is explicitly accepted and never represented as a generated render.
- [ ] `VIDEO` fallback is `PRODUCTION_PACK_ONLY` and contains script, time-coded storyboard, shot list, voiceover, on-screen text, captions, prompts/source assets, edit plan, and output spec.
- [ ] Metadata requirements are recorded for every requested placement.
- [ ] Missing tools never create empty files or invented paths.

## Review, status, and integrity

- [ ] Producers cannot issue the final review or approval of their own assets.
- [ ] Final output separates readiness from performance.
- [ ] `ready` is transactional and runs the complete 12-gate set.
- [ ] `Z-READY.md` references the exact final gate-report SHA-256.
- [ ] Certified-file changes, deletions, symlink substitutions, and unauthorized new files fail `verify-ready`.
- [ ] `Z-READY.md` cannot claim marketing performance.
- [ ] `Z-VALIDATED.md` requires real source data, a predeclared rule, calculation evidence, matching hashes, a passing threshold, and independent review.
- [ ] Source, rule, or calculation changes fail `verify-results`.

## External action

- [ ] External publish, send, schedule, deploy, bid, or spend requires exact explicit human approval.
- [ ] `publish-check` only emits a local scoped permit and performs no external action.
- [ ] Assistant-authored, generic, expired, or self-owned approvals fail.

## Trust boundary

- [ ] Documentation states that local SHA-256 records are integrity links, not digital signatures or identity proof.
- [ ] Provider-specific generation and publication remain explicit integration boundaries.
- [ ] Arbitrary KPI recomputation is not claimed; calculation evidence and independent measurement review remain required.
